Player 테이블 (100만 건)
↓
id 컬럼으로 B+ 트리 생성
🔑 id 인덱스 (B+ Tree)
검색 동작
빠름
WHERE id = 500000
B+ 트리 탐색 → O(log n)
느림
WHERE name = 'T1 Faker'
선형 탐색 → O(n), 100만 건 전부 순회
느림
WHERE id BETWEEN 100 AND 200
리프 연결 리스트 → O(log n + k)
특징
id 검색 O(log n)으로 빠름
메모리 사용 최소화
삽입 시 인덱스 1개만 갱신
name 검색은 여전히 O(n)

🔑 id 인덱스 (B+ Tree #1)
추가된 인덱스
🔤 name 인덱스 (B+ Tree #2) — 문자열 정렬
검색 동작
빠름
WHERE id = 500000
id 인덱스 → O(log n)
추가
WHERE name = 'T1 Faker'
name 인덱스 → O(log n), 이제 빠름
느림
WHERE winrate > 70
인덱스 없음 → 선형 탐색 O(n)
트레이드오프
id · name 검색 모두 O(log n)
메모리 2배 (트리 2개)
삽입 시 인덱스 2개 갱신 → 쓰기 느림

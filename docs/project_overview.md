## 데이터 구조 (Player)

프로젝트 전체에서 다루는 데이터 단위.

```c
typedef struct {
    int   id;       // Primary Key (1 ~ N)
    char  name[32]; // 닉네임 (e.g. "Player_499999")
    int   score;    // 점수 (0 ~ 9999, 랜덤)
    char  tier[16]; // 티어 (Challenger / Diamond / ...)
} Player;
```

## 3가지 탐색 방식

### 1. 선형 탐색 (`src/linear/`)

```
[Player 배열]
 [0] [1] [2] [3] ... [999999]
  →  →  →  →  →  →  찾을 때까지 전부 순회

단일 탐색: 최악 100만 번 비교 → O(N)
범위 탐색: 무조건 전부 순회    → O(N)
```

인덱스가 없을 때 DB가 하는 일. Full Table Scan.

---

### 2. B 트리 (`src/btree/`)

```
               [500000]                   ← 루트 (내부 노드)
              /         \
        [250000]       [750000]           ← 내부 노드
        /      \       /      \
   [125000] [375000] ...               ← 내부 노드
       ...
  [리프들]                               ← 리프 노드

모든 노드(내부 + 리프)에 레코드 포인터 저장
→ 운 좋으면 루트에서 바로 발견 가능
→ 트리 높이 ≈ 4~5 레벨 (ORDER=32)
```

**핵심 특성**
- 노드당 최대 32개 키 (`BT_ORDER = 32`)
- 내부 노드에도 `ptrs[]`(레코드 포인터) 존재
- 분할 방식: **move-up** — 중간 키가 부모로 올라가고 양쪽에서 제거

---

### 3. B+ 트리 (`src/bplus_tree/`)

```
               [500000]                   ← 루트 (내부 노드, 레코드 없음)
              /         \
        [250000]       [750000]           ← 내부 노드 (탐색 경로만)
            ...
  [리프1] → [리프2] → [리프3] → ...      ← 리프 연결 리스트 (레코드 여기에만!)
```

**핵심 특성**
- 내부 노드: 탐색 경로만 안내, 레코드 없음
- 리프 노드: 실제 레코드 포인터 + `next` 포인터로 연결 리스트
- 분할 방식: 리프는 **copy-up**, 내부 노드는 **move-up**
- 범위 탐색: 리프 연결 리스트 순차 스캔 → **압도적으로 빠름**

---

## B 트리 vs B+ 트리 핵심 차이

| | B 트리 | B+ 트리 |
|---|---|---|
| 레코드 위치 | 모든 노드 | 리프만 |
| 리프 연결 | ❌ 없음 | ✅ next 연결 리스트 |
| 단일 탐색 | 일찍 발견 가능 | 항상 리프까지 |
| 범위 탐색 | 트리 전체 재귀 | 연결 리스트 스캔 |
| 리프 분할 | move-up | **copy-up** (리프에 키 유지) |

## 핵심 구현 포인트 (박승현 파트)

### 삽입: `insert_rec()` 재귀 구조

```
insert_rec(node, key, ptr)
    ↓
  리프?
  ├─ YES → memmove로 삽입 → 꽉 차면 split
  └─ NO  → find_pos로 방향 결정 → 자식 재귀
              자식이 분할됐으면 승격 키를 현재 노드에 삽입
              현재 노드도 꽉 차면 다시 split → 상위로 전파
```

### 분할: copy-up vs move-up

```
[B+ 트리 리프 분할 - copy-up]
[10, 20, 30, 40]
       ↓
왼쪽: [10, 20]   오른쪽: [30, 40]   부모로: 30 (복사!)
                           ↑
                      30이 여기 남아있음 (데이터 접근 보장)

[B 트리 / B+ 트리 내부 노드 분할 - move-up]
[10, 20, 30, 40]
       ↓
왼쪽: [10, 20]   오른쪽: [40]   부모로: 30 (이동!)
                                        ↑
                              양쪽에서 30이 사라짐
```

### 범위 탐색: B+ 트리의 결정적 장점

```
B 트리:  재귀로 트리 전체 순회 필요
         O(k log N) 수준

B+ 트리: 1. lo 리프까지 O(log N) 이동
         2. next 포인터로 연결 리스트 순차 스캔 O(k)
         합계: O(log N + k)  ← 훨씬 빠름
```
